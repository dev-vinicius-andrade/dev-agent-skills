# Commit Hygiene (all stacks)

Apply unless the repository defines its own commit, branch or review conventions (`CONTRIBUTING.md`, commit linters, recent `git log`); then follow the repository and say so in the final report.

## Branches

- Branch from the latest integration branch (e.g. `origin/dev`, else `origin/main`). Ask when it is unclear.
- Never branch from release or stage branches.

## Commits

- Small, incremental commits, one concern each (a rename, a move, and a behavior change are three commits).
- Commit only after the relevant build and tests pass and the change is judged correct.
- Subject max 20 characters. Description as bullets, max 15 characters per line, max 15 lines.
- No AI attribution anywhere (no `Co-Authored-By`, no "generated by" lines).
- When a feature or fix is ready, squash its commits into one.

## Hand-off

- Never push; the developer pushes after squashing.
- Never open or suggest opening a pull request; the developer decides when.
